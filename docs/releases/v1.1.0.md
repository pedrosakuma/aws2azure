# aws2azure v1.1.0

> **Release status:** Stable
> **Support window:** `v1.1.x` and, per the compatibility policy, the latest
> patch of the immediately previous minor (`v1.0.x`)

promotion does not rebuild the Native AOT archives or container image;
`v1.1.0-rc.8`'s sealed candidate (`952c333f`) is unchanged from the RC cut.

This matrix announces workload-scoped compatibility, **not full AWS service
parity**. Operations and semantics outside these profiles remain governed by
the gap documentation and are not implied to be supported by this release.

The `release-candidate-promote` readiness plan for this release gates exactly
these two profiles with a fresh, dedicated 60-minute dual-cohort real-Azure
observation window against the sealed `v1.1.0-rc.8` candidate:

## Notable changes since v1.0.0

- Promoted `dynamodb-basic-crud` and `sqs-standard-messaging` to GA.
- Added the real-Azure RC observation pipeline
  (`rc-observation-real-azure.yml`) as a mandatory dual-cohort, ≥60-minute
  promotion gate, replacing ad hoc pre-promotion checks.
- Added the immutable RC manifest, archive, and GHCR-image producer chain
  (`release-candidate.yml`, `release-candidate-image.yml`,
  `release-candidate-manifest.py`) so stable promotion only ever attaches
  already-built and already-observed bytes; it never rebuilds or republishes.
- Defined the formal [versioning and compatibility
  policy](../versioning-and-compatibility.md) governing this and all future
  releases.
- Root-caused and fixed a SecretsManager RC-observation throughput floor
  breach caused by single-runner CPU contention between concurrently
  observed candidate/stable cohorts (see #1007, #1008), rather than the
  previously suspected Key Vault backend contention (#1003).
- Numerous RC pipeline hardening fixes (immutable input verification, ELF
  architecture checks, provenance/attestation alignment, emulator perf
  stabilization) — see the full commit history between `v1.0.0` and
  `v1.1.0-rc.8` for details.

## Install exact promoted bytes

### Container

Use the digest, not a mutable convenience tag:

```bash
docker pull ghcr.io/pedrosakuma/aws2azure@sha256:a0b9341ff7c739846b99d70d44308c46cfdbc814aeaf2f56450c6be0789c30ac
docker run --rm \
  -p 8080:8080 \
  -v "$PWD/config.json:/app/config.json:ro" \
  -e AWS2AZURE_CONFIG_FILE=/app/config.json \
  ghcr.io/pedrosakuma/aws2azure@sha256:a0b9341ff7c739846b99d70d44308c46cfdbc814aeaf2f56450c6be0789c30ac
```

The `v1.1.0` GHCR tag is an alias for this exact existing RC index; promotion
does not build or push a different image.

### Native AOT archive

Download the archive for the target architecture from the `v1.1.0` GitHub
Release, then verify it before extraction:

```bash
sha256sum --check SHA256SUMS.all
tar -xzf aws2azure-v1.1.0-rc.8-linux-x64-9da866d39f2d71c4ba2db03a959db09ee123a87a7322513089f7559f155deb39.tar.gz
```

Use the `linux-arm64` archive and its checksum on arm64 hosts.

## Upgrade and rollback

`v1.1.0` is a MINOR release from `v1.0.0`. Per the compatibility policy, the
supported in-place upgrade/rollback span includes `v1.0.x` (latest patch) to
`v1.1.x`. Configuration schema and persisted formats are unchanged by this
release; review the [compatibility policy](../versioning-and-compatibility.md)
for the exhaustive list of durable-format compatibility guarantees.

Before rollout, retain the exact prior artifact and configuration as required
by the [production runbook](../deployment/production-runbook.md). Both
re-observed profiles verified candidate-write/previous-read behavior and
exact-prior restoration during their observation runs.

To roll back, stop traffic to `v1.1.0`, restore the retained prior executable
and matching configuration, verify `/health`, `/ready`, and the module list,
then restore traffic. Rollback restores code and configuration; it does not
undo Azure writes or credential changes.

## Known incompatibilities and operator actions

- aws2azure translates AWS wire protocols to selected Azure data planes; it is
  not an AWS IAM, control-plane, or full-service emulator.
- This release's dedicated RC observation/readiness gate covers only the two
  profiles listed above. Other profiles carrying a GA verdict in the live
  ledger have not been independently re-verified by this specific promotion
  cycle (see #1009). Review every required operation and accepted gap before
  production use.
- S3 clients must use path-style addressing through the proxy.
- Azure topology, capacity, consistency, throttling, and authorization
  semantics remain Azure-native and can differ from AWS.
